# Databases with SQLAlchemy 2.0

FastAPI doesn't come with a data layer: you plug one in. The standard choice is **SQLAlchemy
2.0**, the same ORM you used with Flask, but here **without an extension**: the session is
handled with a **dependency with `yield`**. A key separation also shows up in typed APIs: the
**ORM models** (the tables) are different from the **Pydantic schemas** (what goes in and out
over HTTP).

## Engine, session and models

```python
from sqlalchemy import create_engine, String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, sessionmaker, Session

engine = create_engine("sqlite:///tasks.db")       # or postgresql+psycopg://user:pass@host/db
SessionLocal = sessionmaker(bind=engine)

class Base(DeclarativeBase):
    pass

class Task(Base):
    __tablename__ = "tasks"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100))
    done: Mapped[bool] = mapped_column(default=False)

Base.metadata.create_all(engine)                    # for real: migrations with Alembic
```

- The **engine** manages the connections (the pool).
- `sessionmaker` is a configured session factory.
- Models use the same typed style (`Mapped`, `mapped_column`) as in Flask-SQLAlchemy.

## The session as a dependency

```python
from collections.abc import Iterator
from typing import Annotated
from fastapi import Depends

def get_session() -> Iterator[Session]:
    with SessionLocal() as session:      # closes itself when the request ends
        yield session

SessionDep = Annotated[Session, Depends(get_session)]
```

Each request gets **its own session**, and it's closed at the end no matter what. In tests, you
replace it via `dependency_overrides` with a session against a **fresh, in-memory** database.

> In-memory SQLite + multiple threads: use
> `create_engine("sqlite://", connect_args={"check_same_thread": False}, poolclass=StaticPool)`,
> so all connections share the same in-memory database.

## ORM models vs. Pydantic schemas

```python
from pydantic import BaseModel, ConfigDict, Field

class TaskCreate(BaseModel):                    # what the client SENDS to create
    title: str = Field(min_length=1, max_length=100)

class TaskUpdate(BaseModel):                    # PATCH: everything optional
    title: str | None = Field(default=None, min_length=1, max_length=100)
    done: bool | None = None

class TaskPublic(BaseModel):                    # what the API RETURNS
    model_config = ConfigDict(from_attributes=True)
    id: int
    title: str
    done: bool
```

Why not use the ORM model directly in the API?

- The client **must not** send certain fields (`id`, `created_by`, `password_hash`).
- The response **must not** expose others (passwords, internal fields).
- The shape of the API and the shape of the table evolve separately.

`from_attributes=True` lets you build the schema **from an ORM object**
(`TaskPublic.model_validate(task)`), and it's what `response_model` does when you return a
`Task`.

> **SQLModel** (by the author of FastAPI) merges both into a single class, at the cost of less
> separation. It's a valid alternative for small projects.

## A complete CRUD

```python
from sqlalchemy import select

@app.post("/tasks", response_model=TaskPublic, status_code=201)
def create(data: TaskCreate, session: SessionDep):
    task = Task(**data.model_dump())
    session.add(task)
    session.commit()
    session.refresh(task)           # reloads the id and the defaults generated by the database
    return task                     # response_model converts it to TaskPublic

@app.get("/tasks", response_model=list[TaskPublic])
def list_tasks(session: SessionDep, done: bool | None = None):
    stmt = select(Task).order_by(Task.id)
    if done is not None:
        stmt = stmt.where(Task.done == done)
    return session.scalars(stmt).all()

@app.get("/tasks/{id}", response_model=TaskPublic)
def detail(id: int, session: SessionDep):
    task = session.get(Task, id)
    if task is None:
        raise HTTPException(404, "task not found")
    return task

@app.patch("/tasks/{id}", response_model=TaskPublic)
def update(id: int, data: TaskUpdate, session: SessionDep):
    task = session.get(Task, id)
    if task is None:
        raise HTTPException(404, "task not found")
    for field, value in data.model_dump(exclude_unset=True).items():
        setattr(task, field, value)
    session.commit()
    session.refresh(task)
    return task
```

### PATCH and `exclude_unset`

In a PATCH, the client sends **only what it wants to change**. `model_dump(exclude_unset=True)`
returns only the fields that came in the JSON. Without it, a PATCH with `{"done": true}` would
overwrite the title with `None`.

## `def` endpoints and the synchronous session

SQLAlchemy with a synchronous driver **blocks**, so these endpoints are `def` and FastAPI runs
them in the thread pool (previous chapter). If you want everything async, there's
`sqlalchemy.ext.asyncio` (`AsyncSession`, `create_async_engine`) with drivers like `asyncpg` or
`aiosqlite`: the code is almost the same, with `await`.

## In the other frameworks

- **Flask**: the same SQLAlchemy, with Flask-SQLAlchemy managing the per-request session.
- **Django**: its own ORM, and DRF's **serializers** play the role of the Pydantic schemas.

## Summary

- Engine and `sessionmaker`; typed models with `Mapped`.
- Per-request session with a `yield` dependency (`SessionDep`).
- Separate schemas: `Create`, `Update` (optional) and `Public` (`from_attributes=True`).
- `session.add/commit/refresh`, `session.get` and `session.scalars(select(...))`.
- PATCH with `model_dump(exclude_unset=True)`.
- `def` endpoints with the synchronous session, or fully async with `AsyncSession`.
